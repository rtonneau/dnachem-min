dnachem-min — source layout review

Direction: cluster the 31 .cc + 33 .hh files (flat src/ and header/) into subdirectories; rename where it helps.

What the exploration found

  • CMake is already ready for subfolders. file(GLOB_RECURSE ...) with CONFIGURE_DEPENDS, and every header directory is added to the include path — so today's short includes ("RunAction.hh") keep compiling after a move. The cost: nothing enforces the clusters, and the include path is flat.
  • Only the 7 test targets and the docs name paths. Test targets hand-list src/*.cc files (e.g. RunAccumulatorTest lists 5 sources); CLAUDE.md (25 refs), README.md (6), 5 macro header comments, .claude/.claude-project.json (test wiring template) and compile_commands.json (regenerated by the PostToolUse hook) refer to paths.
  • Natural clusters exist already, visible from the include graph and the "portable / kernel-free" convention (files with a unit test and no Geant4-kernel dependency).
  • Four cross-cluster couplings that a directory layout would expose: StackingAction → PhysicsList (dynamic_cast just for IsChemistryEnabled()); DnaChemistryList → DetectorConstruction (dynamic_cast to reach the DnaChemistryWorld); PhysicsList.hh → DnaChemistryList.hh; Run.hh includes DetectorConstruction.hh although it only forward-declares it.

1. Cluster files into domain subdirectories Strong

Problem. 64 files in two flat directories; finding "everything about reaction counting" or "everything that selects a Chemistry" means grepping. New Chemistries (per the "add another Chemistry" recipe) and new counters have no obvious home.

Solution. Move files into the cluster tree above, mirrored under src/ and header/. CMake needs no source-list change (GLOB_RECURSE, flat include dirs). Update test source paths, CLAUDE.md Key Files, README.md, macro comments, and let the hook regenerate compile_commands.json. Use git mv so history follows.

Benefits. Locality: a change to chemistry selection stays inside chemistry/. The "portable, kernel-free" files become visible as a set. Low risk: pure moves, verified by a rebuild + the 7 CTest targets + a 10 keV beam.in run diffed against a pre-move output.

2. Rooted includes and header placement Worth exploring

Problem. The flat include path (every header dir added) lets any file include any header by bare name, so the new directories would be cosmetic — nothing stops scoring/ from reaching into chemistry/. Also open: keep the Geant4-style split header/ vs src/, or co-locate .hh next to .cc.

Solution. Include with the cluster prefix (#include "scoring/ReactionCounter.hh"), a single include root (header/, or src/ if co-located), drop the per-directory include loop in CMake. Decide header placement first.

Benefits. Each include documents the dependency direction; cross-cluster edges become greppable. Tension: touches ~100 include lines, and the "copy-paste portable" files would carry a cluster prefix when copied to another project — they may need a small note, or to keep bare includes for their own header only.

3. Per-cluster CMake targets, a kernel-free core library Worth exploring

Problem. Each unit test re-lists its src/*.cc dependencies (RunAccumulatorTest: 5 files; ReactionCounterTest: OutputDir.cc pulled in transitively). Adding a dependency to one class means editing several test targets; a missing one is a link error.

Solution. A static library dnachem_core holding the kernel-free modules (OutputDir, counters, RunAccumulator, ChemistryRegistry, ArgParser, PhysicsInteractionCounter, ...) that tests link, and sim links too. Optionally one object library per cluster.

Benefits. Test wiring shrinks to one line each; the portability convention is enforced by the build (the core library cannot include kernel headers it does not link). Risk: Debug/RelWithDebInfo CRT mismatch pitfalls already recorded for the test binaries — verify in build-ninja/.

4. Remove the four cross-cluster couplings Worth exploring

Problem. StackingAction dynamic_casts the run manager's physics list only to ask IsChemistryEnabled(); DnaChemistryList dynamic_casts DetectorConstruction to reach the DnaChemistryWorld; PhysicsList.hh exposes DnaChemistryList.hh; Run.hh includes DetectorConstruction.hh without needing it.

Solution. Drop the unused include; forward-declare in PhysicsList.hh; pass the chemistry world / chemistry-enabled flag through a small shared interface instead of downcasting. Only worth doing where the move exposes a real cycle between clusters.

Benefits. Cluster dependency direction becomes acyclic (core ← geometry/chemistry/scoring ← actions), so the directory tree tells the truth. Tension: two of the four are Geant4-idiomatic downcasts; changing them is optional.

5. Renames that pay for themselves Speculative

Problem. A few names hide their cluster: ChemUtils (only used by StackingAction, to print the time-step model), RunAccumulatorMessenger (owns the dump/reset commands, not accumulation), BuiltInChemistries vs ChemistryRegistry, Run (generic), PrimaryKiller.hh still guarded by CHEM6_PrimaryKiller_h (Geant4 example residue).

Solution. After candidate 1, rename file and class together only where the new directory does not already disambiguate; fix the stale header guard; consider folding ChemUtils into StackingAction/chemistry/ logging.

Benefits. Marginal on its own; directories remove most of the ambiguity. Renames touch class names, macros' docs and memory notes — do only if a name still misleads after the move.

Ordering: 1 first (independent, low risk) → 2 (decide header placement inside the grill for 1 if preferred) → 3 → 4 → 5.
