# dnachem-min

## Purpose and Scope

Minimal Geant4-DNA example for studying water radiolysis from electron beams. It provides the common physics, chemistry, and scoring basis for conventional and ultra-high-dose-rate (UHDR) irradiation studies.

UHDR is a use case, not a separate implementation: do not add UHDR-specific pulse structure, dose-rate effects or delivery models unless the project scope changes. The one scope change so far (ADR 0006) is the chemistry model below, taken from the Geant4-DNA UHDR example.

The geometry is one homogeneous water box. Do not introduce voxelization or G4Vox-based geometry. The chemistry runs the **Particle-based stage** (IRT_syn, or SBS) and, with IRT_syn, can hand over at the **Hand-over time** to the **Mesoscopic stage** (counts per cell on Geant4's cell mesh, which exists only inside the chemistry, not in the geometry) up to the end time. Three modes are selectable: SBS; IRT_syn alone; IRT_syn + mesoscopic (the default). Pulse structure and multi-track dose effects are future work (stage 2). Design records: `docs/adr/0006-irt-syn-and-mesoscopic-chemistry.md` and `docs/adr/0008-selectable-chemistry-modes.md`.

## Build and Run

Requirements: Geant4 11.0+ with DNA models, CMake 3.16+, a C++20 compiler, and HDF5 with C++ support.

How to build, run and test (MSVC environment, the `build/` vs `build-ninja/` split, background runs, verification checklist) is in `.claude/geant4-instructions.md`; the values it uses are the `build`, `run` and `test` sections of `.claude/.claude-project.json`. Follow it instead of re-deriving the procedure.

Queued/tracked runs and analysis across projects: the global `/g4run` skill, specified (not yet built) in `~/dotfiles/claude/skills/g4run/SPEC.md`; see `docs/agents/g4run.md`.

Project-specific: `build/` is RelWithDebInfo (run `sim`), `build-ninja/` is Debug (ctest). `sim.cc` looks up the macro argument in this order: the argument as given, then `<exedir>/<arg>`, then `<exedir>/macro/<arg>`. Pass the filename only, from the run build dir (the build copies `macro/` there):

```bash
./sim beam.in             # pure-water radiolysis
./sim beam_o2.in          # with dissolved-O2 scavenger
./sim example_sbs.in      # SBS mode; example_irt.in / example_meso.in for the IRT_syn modes
```

Output data (species, mesoscopic species, reactions, physics-interaction counts) accumulates across `/run/beamOn` calls; nothing is written until a macro issues `/run/dumpDataAndReset [prefix]` or `/run/dumpDataAndResetToDir <subdir>`, and a safety-net flush with prefix `EndOfRun_` fires at exit if data is still pending. `Species.*` stops at the hand-over time (particle-based stage; the whole run in SBS or IRT_syn-only mode); `SpeciesMeso.Txt`/`SpeciesMeso.csv` (mean count per event vs. time on the log record grid) cover the mesoscopic stage and are not written when it is off (`/chem/meso/enable false`, or SBS); with `/chem/meso/spatialOutput true` the dump also moves in `SpeciesMesoSpatial.h5` (per-event spatial snapshots of the mesh, see the `sim-output` skill and `docs/output/SpeciesMesoSpatial-h5.md`); `Reactions.*` covers the particle-based stage only (the mesoscopic stage does not record which reaction fired). Every dump also writes a `Manifest.json` (beam, seed, energy deposit, Chemistry, environment, files) beside its data; there is no `EnergyDeposit.Txt`. `--dir <path>` / `/run/outputDir <path>` redirect all output; without either, output goes to `<exeDir>/results` (e.g. `build/results`), whose `Manifest.json` is also the results index listing every dump (`ResultsIndex`, ADR 0005 addendum). File formats, prefix/subdir rules and failure modes: the `sim-output` skill (`.claude/skills/sim-output/SKILL.md`).

## Source layout

Project includes are rooted at `header/`, which is the only project include directory: `#include "chemistry/DnaChemistryList.hh"`. A new file goes in the directory of the concern it belongs to; a new Chemistry goes in `chemistry/catalog/`. Rationale: `docs/adr/0003-clustered-source-layout.md`.

## Key Files

- `sim.cc`: application setup. Runs Serial by default; `--threads N` (N > 0) selects the MT run manager (`G4RunManagerType::MT`), and `/run/numberOfThreads N` in a macro can still override before `/run/initialize`. Set `useGUI` to `true` only for interactive GUI runs. CLI flags (`--threads`, `--dir`) are registered here via `src/core/ArgParser.cc`.
- `src/core/OutputDir.cc`: process-wide output directory (`--dir`), configured once in `main()` before any worker thread starts. `Resolve(filename)` is called at every output-file site (`ScoreSpecies.cc`, `TimeStepAction.cc`, `DnaChemistryList.cc`'s reaction-table dump) to prefix it onto the configured directory, or leaves it unchanged when `--dir` wasn't passed. `ConfigureFromMacro()` backs the `/run/outputDir` macro command (`src/core/OutputDirMessenger.cc`) — same effect as `Configure()` when nothing is set yet, a no-op when the macro repeats the already-configured path, and a fatal `G4Exception` when it differs (raised by the messenger, not by `OutputDir` itself, which stays pure/testable). It also holds a separate filename prefix (`SetPrefix()`/`gPrefix`, distinct from the directory) prepended before the directory join — set by `RunAccumulatorMessenger` around each `/run/dumpDataAndReset` flush, not exposed as its own macro command.
- `src/physics/PhysicsList.cc`: simplified UHDR-style modular list — holds `G4EmDNAPhysics` + `DnaChemistryList` and drives their `ConstructParticle()`/`ConstructProcess()` directly (no string dispatch, no `RegisterPhysics`). Change the EM-DNA physics option by editing the constructor. Sets IRT_syn as the default chemistry time-step model (`/process/chem/TimeStepModel` may select SBS instead, PreInit; the IRT_syn particle-based stage hands over to the mesoscopic stage in `TimeStepAction` when `/chem/meso/enable` is true).
- `src/chemistry/DnaChemistryList.cc`: project chemical stage (`G4VUserChemistryList` + `G4VPhysicsConstructor`) — molecule set, water dissociation, reaction table, time-step model. Replaces macro `/chem/species` and `/chem/reaction/add`. Supports two time-step models, IRT_syn (default) and SBS (`/process/chem/TimeStepModel`, PreInit); classic IRT and other values are fatal. `CheckTimeStepModel` (run at `/run/initialize`) also makes an explicit `/chem/meso/enable true` with SBS fatal and sets the default end time (1 us without the mesoscopic stage, 1 s with it). See `docs/adr/0008-selectable-chemistry-modes.md`. The Chemistry's bulk reactions are registered as per-molecule `G4DNAScavengerProcess` for the particle-based stage and added to the reaction table for the mesoscopic stage (a pair already in the table, e.g. bulk O2 = the tracked `O2`, shares that entry). Owns a `MesoMessenger` and warns when the mesh pixel count is capped. The reaction content comes from the selected **Chemistry** (`/chem/select <name>`, default `PureWater`; see `ChemistryRegistry.cc` and `docs/adr/0002-named-chemistries.md`): its reaction table and its bulk-reaction list. `PureWater` (`PureWaterReactions.cc`) carries the pH-driven acid-base buffer network (`H3Op(B)`/`OHm(B)`, registered as per-molecule `G4DNAScavengerProcess`) and the full O2⁻/HO2/HO2⁻/O⁻/O3⁻ network, baseline/unconditional for that Chemistry — it can produce O2 from pure water radiolysis on its own (see `docs/adr/0001-baseline-acid-base-buffer.md`); another Chemistry may supply a partial or empty bulk-reaction list. Molecules and dissociation channels are shared by all Chemistries. Exogenous scavengers (`/chem/env/scavenger`, `DnaChemistryWorld`) react through the Chemistry's bulk reactions (`docs/adr/0004-scavenger-reactions-per-chemistry.md`). Also owns `/chem/reaction/timeBinsFixed` / `timeBinsList` (`ApplyReactionTimeBinning()`, applied from `RunAction::BeginOfRunAction` once the scheduler end time is final) and `/chem/reaction/dump`.
- `src/chemistry/TimeStepAction.cc`: per-thread chemistry time-step action. Runs the particle-based stage; with IRT_syn and `/chem/meso/enable true`, at the first step reaching the **Hand-over time** it passes the remaining molecules to a per-thread `G4DNAEventScheduler` (mesoscopic stage, Gillespie on a cell mesh) that runs to the scheduler end time, recording on a log grid (`MesoSettings::LogTimeGrid`); the molecule counter is muted after the hand-over. Counts reactions live into `ReactionCounter` (particle stage only) and fills a `MesoSpeciesCounter`. Known benign warning: `G4DNAEventScheduler::InitializeInMesh` prints `WrongResolution` once per event (effective radii of D=0 bulk partners, unused by the Gillespie method).
- `src/chemistry/MesoSettings.cc` (+ `header/chemistry/MesoSettings.hh`): portable (standard library only, adjust the include path prefix on copy) mesoscopic-stage settings — process-wide `Values` (`Current()`: hand-over time, requested voxel size, record times per decade), `PixelCount` (power-of-2 pixels per side closest to the requested cell size, capped at 65536 because `G4DNAMesh::ConvertIndex` overflows `int` above that, ADR 0006; on the default 1 mm box this gives 15.26 nm cells instead of 6.25 nm) and `LogTimeGrid`. Pure logic, covered by `test/MesoSettingsTest.cc`.
- `src/chemistry/MesoMessenger.cc`: `/chem/meso/enable` (PreInit bool, default true; false = particle stage only, no hand-over, no `SpeciesMeso*` output), `/chem/meso/handOverTime`, `/chem/meso/voxelSize`, `/chem/meso/timesPerDecade` (all PreInit; non-positive values are fatal) and `/chem/meso/spatialOutput` (PreInit bool), writing `MesoSettings::Current()`.
- `src/scoring/MesoSpeciesCounter.cc`: portable, project-agnostic mesoscopic species counter (`Add`/`Merge`/`Clear`/`WriteAscii`/`WriteCsv`, stream-only I/O) — time → species → summed count, written as `SpeciesMeso.Txt`/`SpeciesMeso.csv`. Covered by `test/MesoSpeciesCounterTest.cc`.
- `src/scoring/MesoSpatialFile.cc` (+ `header/scoring/MesoSpatialFile.hh`): portable (standard library and HDF5 C++ only, adjust the include path prefix on copy) HDF5 writer for the mesoscopic spatial snapshots. `TimeStepAction` appends each event (`AppendEvent`, thread-safe) to the staged `<outdir>/.pending_meso_spatial/SpeciesMesoSpatial.h5`; `RunAccumulatorMessenger` calls `MoveStaged` at every dump (including the `EndOfRun_` safety net) and lists the file in `Manifest.json`. Layout `/run<R>/event<E>/snapshot<k>/` with `position_nm` (N x 3) and `counts` (N x S uint32), attributes `time_ns`, `cellSize_nm`; only non-empty cells are written (format version 2). Format description: `docs/output/SpeciesMesoSpatial-h5.md`.
- `src/scoring/ReactionCounter.cc`: per-time-bin bimolecular reaction-firing counts. Kernel/DLL-free by design (see file header) — `ConfigureBinEdges`/`ParseBinEdgesList` are covered by `test/ReactionCounterTest.cc`; do not call `G4UnitDefinition::GetValueOf()` from here or its test (observed to corrupt memory when the Debug test binary links a differently-built Geant4 install — use the local `TimeUnitValue` table instead).
- `src/chemistry/catalog/PureWaterReactions.cc`: the `PureWater` Chemistry — portable, project-agnostic builders `PureWaterReactions::BuildPureWaterReactions` (the 9 base pure-water reactions plus the full O2-derived second-order network from the Geant4-DNA UHDR example) and `BuildPureWaterBulkReactions` (the bulk-reaction list as plain data, `ChemistryTypes::BulkReactionList`: the acid-base buffer equilibria plus the three dissolved-O2 scavenger reactions `e_aq`/`H`/`Om` + O2(bulk) at UHDR rates, inert while `/chem/env/scavenger O2` is 0; with bulk O2 set, O2 produced by a bulk reaction joins the bulk pool, see ADR 0004). No dependency on other `dnachem-min` classes besides `ChemistryTypes.hh`; copy-paste portable to another project (adjust the include path prefix on copy).
- `src/chemistry/catalog/BoscoloChemReactions.cc`: the `BoscoloChem` Chemistry: exactly Table 1 of Boscolo et al., Int. J. Mol. Sci. 2020, 21, 424 (26 reactions; bulk list = only e_aq/H + O2(bulk); no acid-base buffer, so `/chem/env/pH` has no chemical effect under it). To add another Chemistry: copy `PureWaterReactions.{hh,cc}`, rename, register it in `src/chemistry/BuiltInChemistries.cc`.
- `src/chemistry/catalog/Tonneau2025Reactions.cc` (+ `Tonneau2025Table.cc`, plain-data Table 2 covered by `test/Tonneau2025TableTest.cc`): the `Tonneau2025` Chemistry: the 73-reaction network of Table 2 of Tonneau et al., Phys. Med. Biol. 70 (2025) 235021, with the HO3 **Extra molecule** (parameters: `docs/literature/ho3-parameters.md`, hook: `docs/adr/0007-extra-molecules-per-chemistry.md`). HO3 is added to the molecule table only while `Tonneau2025` is selected, so it is a species column in `Species.*`, `SpeciesMeso.*` and `SpeciesMesoSpatial.h5` for that Chemistry only. The paper starts its ODE at 100 ns; here the network acts from the pre-chemical stage. Quick G-value check at 100 ns against the paper's Table 3: `macro/beam_tonneau2025.in` and `.work/sessions/2026-10-06__homogeneous-chemistry-prechemical-extension/analysis/` (indicative only: 10 keV electrons vs the paper's 1.17 keV/um).
- `src/chemistry/ChemistryRegistry.cc` (+ `header/chemistry/ChemistryTypes.hh`): portable (adjust the include path prefix on copy) name → Chemistry registry and the once-per-process, case-insensitive selection (`Register`/`Select`/`Selected`/`Names`; the default is `PureWater`). Pure logic that only stores builder function pointers, covered by `test/ChemistryRegistryTest.cc`; reports errors as `bool` + string, the messenger raises the `G4Exception`.
- `src/chemistry/BuiltInChemistries.cc`: registers `PureWater`, `BoscoloChem` and `Tonneau2025`; `Register()` is idempotent and called from the `DnaChemistryList` constructor, before any macro can select one.
- `src/chemistry/ChemistrySelectMessenger.cc`: `/chem/select <name>` (PreInit) and `/chem/list`. A plain `G4UImessenger` attached to the existing `/chem/` directory (created by `G4DNAChemistryManager`), not a `G4GenericMessenger`, which would create a second `/chem/`.
- `src/scoring/PhysicsInteractionCounter.cc`: portable, project-agnostic string-frequency counter (`Record`/`Merge`/`Clear`/`WriteAscii`/`WriteCsv`, stream-only I/O, no dependency on other dnachem-min classes) — copy-paste portable to another Geant4-DNA project (adjust the include path prefix on copy), same convention as `PureWaterReactions.cc`.
- `src/scoring/RunAccumulator.cc`: process-wide accumulator for energy deposit, event count, the two counters (`ReactionCounter`, `PhysicsInteractionCounter`) and one manifest run entry (`DataNode`) per run (`AddRunEntry`/`GetRunEntries`, built by `RunManifest::RecordRun`), persisting across `/run/beamOn` calls — pure logic, no Geant4-kernel dependency, covered by `test/RunAccumulatorTest.cc`. Fed once per run from `RunAction::EndOfRunAction` (the beam is sampled by `PrimaryGeneratorAction` into the worker `Run` on the first event and carried by `Run::Merge`; the seed is read when the `Run` is created); species yields don't need this (the `ScoreSpecies` scorer is itself persistent).
- `src/scoring/RunAccumulatorMessenger.cc`: exposes `/run/dumpDataAndReset [prefix]` (`Idle` state) — writes everything accumulated since the last dump (species via a direct `ScoreSpecies` lookup, the rest via `RunAccumulator`), then moves the staged per-event pre-chemical files (`PreChemical_run<R>_event<E>.txt`, staged in `<outdir>/.pending_prechem/` by `EventAction`) into the dump via `PreChemicalFiles::MoveStaged` and lists them in the manifest, then `Manifest.json` via `RunManifest::Write`, then resets it; `prefix` is prepended literally to every output filename via `OutputDir::SetPrefix`. Refuses to reuse a prefix already used earlier in the process (fatal `G4Exception`). Also exposes `FlushIfPending()`, called once from `sim.cc` right before the run manager is destroyed, as a safety net (fixed prefix `EndOfRun_`) for data never manually flushed.
- `src/scoring/DataNode.cc` + `src/scoring/JsonWriter.cc`: portable, project-agnostic (standard library only, adjust the include path prefix on copy) structured-output pair — `DataNode` is a format-neutral ordered tree (null/bool/integer/double/string/array/object; `Add` on an existing key replaces it in place), `JsonWriter::Write(std::ostream&, const DataNode&)` serialises any tree without knowing its keys (12 significant digits, non-finite → `null`, all-scalar containers on one line, others indented). Covered by `test/JsonWriterTest.cc`. Another output format would be a new writer reading the same tree.
- `src/scoring/RunManifest.cc`: the Geant4-facing collector and the **only place listing the manifest's entries** — `RecordRun(const Run&, double wallTime_s)` (from `RunAction::EndOfRunAction`, which times master Begin→EndOfRunAction) builds each run's entry (`run`, `events`, beam or nulls, `energyDeposit_eV`, `seed`, `wallTime_s`) into `RunAccumulator`; `Write` builds the top-level tree (including the model keys `chemistryModel`, `handOverTime_ns`, `voxelSize_nm`, `mesoPixels`, `mesoTimesPerDecade`) from its own steady clock (`elapsedSinceStart_s` since `MarkProcessStart()`, `elapsedSincePreviousDump_s` since the previous dump), the selected Chemistry, `DnaChemistryWorld` (pH, scavengers), the run manager (mode, threads), `OutputDir` and `RunAccumulator` (totals, run entries), and writes `Manifest.json` through `JsonWriter` and `OutputDir::Resolve` (a failed open is a `JustWarning`). Adding/removing an entry is one `Add` line here. `MarkProcessStart()` and `SetMacroName()` are called from `sim.cc`. Design record: `docs/adr/0005-manifest-per-dump.md`.
- `src/actions/SteppingAction.cc`: per-step physical-interaction counting — records `G4Step::GetPostStepPoint()->GetProcessDefinedStep()->GetProcessName()` into a `PhysicsInteractionCounter` whenever the name contains `"G4DNA"` (discrete G4DNA physics processes only, excludes `Transportation`).
- `macro/*.in`: runtime beam and chemistry configuration. Prefer macro changes for species and reaction studies rather than hard-coding them.

## Macro and Logging

Common macro controls include `/run/initialize`, `/run/outputDir <path>` (macro-file counterpart to `--dir`, see above), `/run/dumpDataAndReset [prefix]` / `/run/dumpDataAndResetToDir <subdir>` (dump-and-reset accumulated output, into filename-prefixed files or a subfolder, see above), `/gun/particle e-`, `/gun/energy`, `/chem/meso/handOverTime <value> <unit>` (default 5 ns) / `/chem/meso/voxelSize <value> <unit>` (requested cell size, default 6.25 nm, capped at 65536 pixels per side with a `DnaLogger` warning) / `/chem/meso/timesPerDecade <n>` (default 10) / `/chem/meso/spatialOutput <bool>` (default false; write the per-event mesh snapshots to `SpeciesMesoSpatial.h5`, ~30 MB per 10 keV event at a 1 ms end time; example `macro/beam_meso_spatial.in`) (all PreInit, see `MesoMessenger.cc`), the chemistry end time (default 1 s with meso, 1 us without; set on `/run/initialize`; override with `/scheduler/endTime <value> <unit>` *after* `/run/initialize`), `/chem/select <name>` (PreInit, before `/run/initialize`; case-insensitive; default `PureWater`; an unknown name, or two different names in one process, is a fatal `G4Exception`) and `/chem/list` (print the available Chemistries), `/chem/env/scavenger <species> <value> <unit>` (PreInit; `M`/`mM`/`uM`, or `%` for O2 only with kH = 0.0013 M; repeat = last wins; 0 = absent; an unknown unit, a negative value, `%` on another species or a pH-owned species (`H2O`, `H3Op(B)`, `OHm(B)`) is fatal at the command; a species not in the molecule table is fatal at `/run/initialize`; a species that no bulk reaction of the selected Chemistry uses triggers a `DnaLogger` warning), `/chem/env/halfBox <value> <unit>` (PreInit; half side of the water box, default 500 um; must be > 0, else fatal; the box is the whole geometry — the world volume, the chemistry diffusion boundary and the bulk-scavenger volume, so it also sets how many bulk scavenger molecules exist; recorded as `halfBox_um` in `Manifest.json`), `/chem/env/pH <double>` (still active — drives the bulk H3O+(B)/OH-(B) buffer concentration used by the acid-base network of Chemistries that have one, e.g. `PureWater`; none under `BoscoloChem`), `/chem/reaction/timeBinsFixed <width> <unit>` / `/chem/reaction/timeBinsList <e1> ... <eN> <unit>` (reaction-count time binning, see above), and `/run/beamOn`. Species and reactions are defined in `src/chemistry/DnaChemistryList.cc`/`src/chemistry/catalog/PureWaterReactions.cc`, not via `/chem/species` / `/chem/reaction/add` — do not re-add those to macros (`/chem/reaction/UI` resets the shared reaction table and wipes the class-built one). Chemistry mode: `/process/chem/TimeStepModel SBS|IRT_syn` and `/chem/meso/enable true|false` (both PreInit, before `/run/initialize`; IRT_syn + meso is the default; the mesoscopic stage exists only after IRT_syn, and SBS with an explicit `enable true` is fatal). The default end time is 1 us without meso and 1 s with it; `/scheduler/endTime` after `/run/initialize` overrides it. Mode-example macros: `example_sbs.in` (SBS), `example_irt.in` (IRT_syn, `/chem/meso/enable false`), `example_meso.in` (IRT_syn + meso, with a 1 ms end time after `/run/initialize` so it stays smoke-sized). Each runs 10 keV e-, dissolved O2 21 % (commenting out that one line gives pure water), and two sub-runs of `/run/beamOn 2` with different `/random/setSeeds`, dumped to `sub_01/` and `sub_02/`; the results index is `results/Manifest.json` (or `<--dir>/Manifest.json`). Do not add `/run/outputDir` to them. Other example macros: `beam.in` (pure water, default Chemistry), `beam_02.in` (Meesungnoen2002 solvation, explicit `/chem/meso/*` defaults, scheduler diagnostics), `beam_o2.in` (sets `/chem/env/scavenger O2 21 %`; pH = 7), `beam_boscolo.in` (sets `/chem/select BoscoloChem`, 10 keV, `/run/beamOn 2`), `beam_tonneau2025.in` (sets `/chem/select Tonneau2025`, hand-over time 100 ns, end time 200 ns, 10 keV, `/run/beamOn 2`, dumps; for the 100 ns G-value check). The chemistry-mode examples are listed above.

Use the project-defined `DnaLogger` for application logging. Set its level in a macro with:

```text
/dnaLogger/verbose Quiet|Error|Warning|Info|Debug|Trace
```

The logger is implemented in `src/core/DnaLogger.cc` and exposed to Geant4 commands by `src/core/DnaLoggerMessenger.cc`. Use `/dnaLogger/verbose Debug` for detailed diagnostics; do not add ad hoc console logging where `DnaLogger` is appropriate.

## Testing

Unit tests (`test/*Test.cc`, plain `assert` + CTest) must be built and run from `build-ninja/` (Debug); see `.claude/geant4-instructions.md` section 5 for the `NDEBUG` and Debug-CRT-dialog pitfalls.

When testing `sim.exe`, use a 10 keV electron gun and `/run/beamOn 2` (a full 1 s end time is slow; for a quick smoke run issue `/scheduler/endTime 1 ms` after `/run/initialize`). The chemistry time limit defaults to 1 s with the mesoscopic stage and 1 us without it, set by `G4Scheduler::Instance()->SetEndTime(1. * s)` in `src/actions/ActionInitialization.cc::Build()`, which runs on `/run/initialize`. To override it in a macro, issue `/scheduler/endTime <value> <unit>` *after* `/run/initialize` — a command issued before that point gets overwritten by `Build()`'s hardcoded call.
